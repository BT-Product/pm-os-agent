Ship plan

How I'd ship Cortex

The autonomy dial per segment, where it sits on the trust ladder, how it deploys, what it returns, and how I keep it safe.

01 · Dial

Autonomy per segment

Me, as the PM who built Cortex → Supervised. A mistaken company-wide send is hard to reverse and seen by a lot of people, so every item still gets approved before it goes out — even though I have the most context to trust Cortex's pulled data.

Exec stakeholder (final summary only) → Bounded-autonomous. They trust my supervised review as their checkpoint. That checkpoint doesn't rest on one person's attention: another PM is the named backup reviewer for when I'm out, and exec-facing updates get an independent weekly spot-check on top of my normal review.

Another team's PM (no product context) → Assisted. They lack the context to catch a subtle wrong claim, so they do the task themselves while Cortex only suggests — building the calibration to move up to supervised later.

02 · Ladder

Rung + eval gate

Current rung: Supervised — Cortex drafts everything (update + stories), the critic validates it, and every item holds at the HITL checkpoint before anything happens.

Eval gate to Bounded-autonomous: ≥95% pass rate on EV-1/EV-2/EV-4 (tool-call accuracy, path quality, task completion) AND 0% policy-violations on EV-5 (safety/jailbreak), sustained over 4 weeks of real supervised runs.

Clean incident record: Zero HITL-caught errors required for that window to count as clean.

03 · Deploy

Where it runs & who owns it

Runtime: Serverless — fires on the hook/cron event, nothing running between invocations. An always-on server would waste resources for an event-driven agent.

On-call: I own product-level issues since I'm already reviewing every item. Infrastructure failures go to a formal weekly engineering on-call rotation with PagerDuty-style paging and a 30-minute acknowledgment SLA — not just a name on a doc.

Rollback: Revert code for an actual bug/regression; drop the dial a rung for a trust regression — downgrade before diagnosing.

Monitoring: A dashboard reading run-output/ + the cost estimates agent.py already prints — escalation rate, cost-to-serve, eval pass %, trust incidents.

04 · ROI

Value, not activity

MetricTarget
Outcome — % updates ship with zero manual rewrite70% (hypothesis — unproven on mock fixtures until validated against real traffic once the connector lands)
Cost-to-serve<$0.01 avg per accepted update; monthly aggregate tied to the $20/day cap
Trust incidentsZero per month

Widen rule: Cortex moves to Bounded-autonomous only when the eval gate above holds for 4 weeks with zero incidents.

05 · Governance

How I keep it safe

Compliance: No customer PII touches Cortex today. If that changes, PII gets scrubbed before it ever reaches a fixture Cortex reads — not filtered after the fact.

Safety: Tone/commitment decisions and posting/approving a company-wide update always require a human, for every segment — the agent line never moves. Kill switch is tiered: trigger-disable for a pause, API-key revocation for a full stop.

Reliability: Caps from M5 (8 iterations, 90s timeout, $0.50/run + $20/day, 10-story cap), escalate-on-stuck, fail-closed on model outage.

Strategy: Next widen target is a real Jira/GitHub connector replacing the mock fixtures, gated on EV-1/EV-2/EV-4 re-passing against real data.

Build insights

What I learned

The honest three: where it hurt, what clicked, and the moment something changed.

😵 Friction

The missing-data escalation path was friction I didn't catch myself — it came up during review across M4, M5, and M6. When Cortex hits a project that doesn't exist, it searches every other real project first, burning most of the iteration budget before giving up. Still safe, but inefficient — and if this hit real traffic, it would waste spend on exactly the case that should be cheapest to handle.

🧠 Learning
  1. Evals are much more than LLM-as-judge. What I built was broader — trajectory evals grading the path, a failure-mode register, bounds that trip in code, and a replay set to catch regressions.
  2. "Capability is not permission" is enforced in code, not prompts. The jailbreak probe proved it — the injection got nowhere because the tools to post/close/commit simply don't exist.
  3. Autonomy and the agent line are two different knobs. The agent line is the structural ceiling, same for everyone; the dial only changes how many below-the-line checkpoints pause for a given person. No matter the setting, Cortex never sends anything on its own.
💡 Aha

The golden rule: if something isn't reversible, has a big blast radius, and can't be measured, it shouldn't be automated — it should sit below the line, a human decision. I kept coming back to this across the whole build: the M1 agent line, scoring the critic's checks, JIT permissions, and the M6 autonomy dial per segment.
